# PROGRAMARIS Tenancy v0.2.0 — development certification record

**Status:** release-preparation work authorized; stable publication remains gated by security/integration and tagged artifact certification.

## Scope

- Provider-neutral tenant registry and access validation contracts.
- Endpoint-scoped host browser/OIDC selection adapters with conflict/duplicate detection.
- Independent selected, validated and authorized contexts; authentication before registry lookup.
- Host failure response policy plus generic anonymous registry-failure metadata.
- Independent selected and authorized tenant contexts in ASP.NET Core.
- Optional, fail-closed tenant authorization pipeline requiring host-provided store/validator implementations.
- Explicit outbound HttpClient tenant capture, HTTPS exact-origin allowlist, no automatic redirects or shared cookies.
- Endpoint-scoped operation metadata delivered to the host's trusted `ITenantAccessValidator`.
- `Programaris.Tenancy.Http` binary compatibility for both `net8.0` and `net10.0`.
- Four synchronized NuGet packages: Abstractions, Tenancy, AspNetCore and Http.

## Release gates

1. Windows and Linux Release build and full test suite green on the **final** source commit.
2. All eight .nupkg/.snupkg artifacts validated, including provenance, dependency inventory and exact SourceLink mapping for both `net8.0` and `net10.0` HTTP targets.
3. Explicit authentication/authorization grant, denial, absence, outage and concurrency scenarios tested.
4. Review public v0.1.0 compatibility, certify browser source trust checks and validate a real Gateway + Identity adapter integration.
5. Prove generic public-denial equivalence, no anonymous protected registry lookup and no authorized context on public endpoints.
6. Verify tenant slug grammar including consecutive internal hyphens.
7. Prepare RC, verify immutable package checksums and source SHA, then obtain explicit authorization to promote to stable.
8. Only after the v0.2.0 production readiness review may PRF integration or installer work resume.

The Identity-backed adapter is a consumer responsibility at this stage; the public SDK does not include private Identity implementation, connection credentials or membership policy.
